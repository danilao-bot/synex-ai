# Synex AI — Sample Generated Outputs

This folder contains **real sample outputs** generated by the Synex AI agent,
grounded in DataHub metadata.

These samples let judges evaluate output quality without needing to run the system.

---

## Files

| File | Description |
|---|---|
| `fct_revenue_model.sql` | Production Snowflake dbt SQL model for `prod.sales.fct_revenue` |
| `fct_revenue_schema.yml` | dbt `schema.yml` contract with column tests and governance annotations |

---

## How These Were Generated

1. User typed in Synex Workspace Studio:
   > *"Build a production dbt model for the fct_revenue dataset, mask all PII columns"*

2. Synex agent executed the 6-step plan:
   - **ENTITY_DISCOVERY** — searched DataHub catalog for `fct_revenue`
   - **GOVERNANCE_AUDIT** — fetched schema, found PII tags on `customer_email`, `customer_phone`
   - **LINEAGE_TRAVERSAL** — traversed 2-hop upstream lineage, resolved `stg_orders` as source
   - **CODE_SYNTHESIS** — called GPT-4o via OpenRouter with full DataHub metadata context
   - **VALIDATION** — compiled SQL via SQLGlot, ran dry-run in DuckDB sandbox with real schema
   - **DATAHUB_WRITEBACK** — emitted MCP to document the model back in DataHub

3. User typed a follow-up:
   > *"Add a 7-day rolling average of revenue and exclude cancelled orders"*

4. Synex loaded the previous SQL from session memory (Supabase `synex_runs`) and modified it.

---

## Key Governance Features in the Output

- `SHA2(customer_email, 256)` and `SHA2(customer_phone, 256)` — automatic PII masking
- `WHERE order_status != 'CANCELLED'` — business rule from DataHub description metadata
- `revenue_7d_rolling_avg` — added from conversational follow-up using session memory
- dbt `schema.yml` with `not_null`, `unique`, `accepted_values`, and `relationships` tests
- All governance decisions annotated with inline SQL comments
